# 管理页列表化改造设计（技能 / 任务 / MCP）

日期：2026-10-14
状态：已确认（阶段 4–5 成稿，副标题信息取舍已确认，进入实现）

## 1. 问题定义

管理类页面（技能、MCP、定时任务）目前页面顶部有一段说明文案，正文用**多列卡片网格**
展示条目。卡片占用纵向空间大、一屏可见条目少，浏览效率低。

用户要求：

1. 删除页面顶部说明文案。
2. 卡片展示改为**列表形式**（单列行式），覆盖：任务、市场、内置、我的、已安装、
   MCP（2026-10-14 确认 MCP 卡片也纳入）。
3. **专家套件页（Kits，含市场 / 已安装 tab）本次不改**（2026-10-14 确认），
   仅删除其页面说明文案。

## 2. 现状与范围映射

| 页面 | 文件 | tab | 卡片现状 | 说明文案键 |
| --- | --- | --- | --- | --- |
| 技能 | `src/renderer/components/skills/SkillsManager.tsx` | 市场 / 内置 / 我的 | 卡片网格 `minmax(280px,1fr)` | `skillsDescription` |
| MCP | `src/renderer/components/mcp/McpManager.tsx` | — | 卡片网格 `minmax(280px,1fr)` | `mcpDescription` |
| 任务 | `src/renderer/components/scheduledTasks/ScheduledTasksView.tsx` + `TaskList.tsx` | — | 卡片网格 `minmax(320px,1fr)` | `scheduledTasksPageSubtitle` |
| 专家套件 | `src/renderer/components/kits/KitsManager.tsx` | 市场 / 已安装 | 卡片（`min-h-[116px]`）**保持不动** | `kitDescription` |

- 四个说明文案键各只被对应页面使用一处，删除无外溢。
- 技能页三个 tab（市场 / 内置 / 我的）均在列表化范围内。
- 共享文案样式在 `src/renderer/components/common/managementTypography.ts`。

## 3. 需求规格

### FR-1: 删除页面说明文案

- 删除四个页面顶部说明文案的渲染（各文件中的一处 `i18nService.t(...)`）。
- `skillsDescription` / `kitDescription` / `mcpDescription` / `scheduledTasksPageSubtitle`
  四个键的中英文条目从 `src/renderer/services/i18n.ts` 同步删除，不留死键。
- 页面标题与操作区（搜索、tab、新建按钮等）保持不变。

### FR-2: 卡片改列表

卡片 → 单列列表行，范围：

| 范围 | 对应 |
| --- | --- |
| 任务 | `TaskList` 的任务卡片 |
| 市场 | 技能页 marketplace tab |
| 内置 | 技能页 builtIn tab |
| 我的 | 技能页 mine tab |
| MCP | `McpManager` 的 MCP 卡片（2026-10-14 确认纳入） |

- 单列列表，每行一条，不再使用多列网格。
- **行内信息与卡片等价，不丢失**：左侧图标 + 名称 + 副标题（元信息），右侧状态徽标
  与操作按钮（安装 / 已安装 / 启用开关 / 溢出菜单等）；长描述截断省略。
- 行高适中（建议 `py-3`），hover 高亮，键盘 focus 可达。
- 行间用分隔线（`divide-y`）或紧凑间距，整块容器统一边框/背景观感。
- **不做清单**：
  - **专家套件页（Kits）保持卡片展示**，仅删说明文案（2026-10-14 确认）。
  - 不改搜索、tab 切换、标签过滤、排序等行为。
  - 不改各条目的点击行为与操作逻辑（任务 → 详情、技能/MCP 点击/菜单不变）。

## 4. 列表行设计

单行结构（以技能行为例，任务/MCP 同构）：

```
┌──────────────────────────────────────────────────────────┐
│ 名称                               [状态徽标] [操作按钮] [⋮] │
│ 副标题（描述摘要 / 任务 cron 摘要 / 命令摘要等）               │
└──────────────────────────────────────────────────────────┘
```

- **无图标**：技能 / MCP 列表行与详情弹窗不渲染图标 tile，行首直接是名称
  （2026-10-15 确认）；任务列表本就无图标。技能选择弹层（`SkillsPopover`）
  不在此范围，保留图标。
- 副标题按页面取最有用的一行元信息（2026-10-14 确认）：
  - 技能：安装来源 / 描述摘要；
  - 任务：cron 表达式 / 下次执行时间 / 描述摘要；
  - MCP：传输方式 / 命令或 URL 摘要；
  - 详情类长文本（完整描述、示例提示词等）仍留在详情视图，不进列表行。
- 空态、加载骨架屏、无结果态保持原逻辑，骨架屏同步改为行式占位。

## 5. 交互设计

- 空态：沿用各页现有空态文案与引导按钮，仅外层从网格容器改为列表容器。
- 加载：骨架屏改为行式占位，占位行数与现状网格一致。
- 异常：加载失败提示不变。
- 边界：名称过长截断省略；操作按钮空间不足时优先保留主操作，溢出菜单兜底。

## 6. 架构方案

- `TaskList.tsx`：`cardGridClass` 改为单列容器，`TaskCard` 改行式渲染。
- `SkillsManager.tsx`：内联卡片渲染改为列表行。
- `McpManager.tsx`：卡片网格改列表行（`McpCard` 改行式渲染）。
- `KitsManager.tsx`：**不改**（仅删说明文案）。
- 三个页面的行结构高度同构，抽一个共享行组件
  `src/renderer/components/common/ManagementListRow.tsx`，承载布局与 hover/focus
  行为，各页传入名称/副标题与右区（徽标/操作）内容（技能 / MCP 不传图标，
  见第 4 节）；共享样式复用 `managementTypography.ts`。
- 纯 renderer 改动，不涉及主进程与 IPC。

## 7. 验收标准

1. 技能 / 能力包 / MCP / 任务四页顶部无说明文案，`i18n.ts` 中四个键（中英）已删除，无残留引用。
2. 任务列表为单列行式。
3. 技能页市场 / 内置 / 我的三个 tab 均为列表展示。
4. **专家套件页市场 / 已安装两个 tab 保持卡片展示不变**。
5. 列表行信息与原卡片等价：名称、元信息、状态徽标、操作按钮齐全。
6. 空态 / 加载骨架屏 / 无结果态在各 tab 下表现正确。
7. 搜索、tab 切换、标签过滤、点击行为与操作逻辑与改造前一致。
8. MCP 页为列表展示，信息与操作与原卡片等价。
9. 中英文界面均无遗漏旧文案。
10. 改动文件在 CI 同款 eslint（`--max-warnings 0`）下通过；typecheck / `npm run build` 通过。

## 8. 已确认决定

2026-10-14 与用户确认：

1. 列表行副标题按第 4 节默认方案（各页取一行最有用的元信息，长描述留在详情）。
2. MCP 卡片纳入列表化范围。
3. **专家套件页（Kits，含市场 / 已安装）本次不列表化**，保持卡片，仅删说明文案。

### 8.1 列表行 / 详情弹窗完全去掉图标（2026-10-15 确认）

2026-10-15 用户改定：管理页**不需要图标**。

- 技能 / MCP 列表行与详情弹窗不再渲染图标 tile，行首直接是名称 + 副标题。
- `McpCard.tsx` 中的 `McpIconTile` 组件与 `icon` / `category` 透传已删除；
  `McpDetailModal` 的 `icon` / `category` props 已删除。`icons/ConnectorIcon.tsx`
  因零引用一并删除。
- `SkillsManager` 各列表行与详情弹窗已去掉图标；`SkillIconTile.tsx` 保留，
  仅 `SkillsPopover`（技能选择弹层，不在列表化范围）继续使用。
- 任务列表本就无图标；专家套件页保持卡片不动。

补充（2026-10-15）：曾评估「按类别映射字形」的替代方案（连接器按 `category`、
技能按 `tags` / 关键词推断类别），**确认不做**，管理页维持无图标。原因是
`Skill` 类型没有分类字段，技能侧只能靠关键词推断，准确率不足以支撑视觉语义；
两处类别的真实图标链路（`MarketplaceSkill.icon` / `McpRegistryEntry.icon`）
仍待服务端下发，届时走真实图片而非生成字形。
